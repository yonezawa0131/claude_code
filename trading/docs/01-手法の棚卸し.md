# デイトレード分析手法の棚卸し

「デイトレーダーの分析手法をビットコインに適用できるか」を整理する。

分類の軸は**検証できるかどうか**にした。効きそうかどうかではない。
効くかどうかは測って決めることで、測れないものは採用の判断そのものができない。

---

## 検証可能性の3段階

| 段階 | 意味 |
|---|---|
| **A. すぐ検証できる** | OHLCVだけで計算でき、定義が一意。同じデータからは誰が計算しても同じ値になる |
| **B. データが足りない** | 定義は一意だが、板情報やティックデータが必要。日足・時間足のOHLCVからは計算できない |
| **C. 定義が一意でない** | 人によって引き方・数え方が変わる。機械化しないと検証できない |

---

## A. すぐ検証できる手法

OHLCVから計算でき、定義が一意に決まるもの。**この基盤でそのまま測れる。**

### 実装済み

| 手法 | 種類 | 実装 |
|---|---|---|
| SMA / EMA | トレンド | `indicators.sma` / `ema` |
| MACD | トレンド | `indicators.macd` |
| RSI（Wilder方式） | オシレーター | `indicators.rsi` |
| ATR（Wilder方式） | ボラティリティ | `indicators.atr` |
| ボリンジャーバンド | ボラティリティ | `indicators.bollinger` |
| 実現ボラティリティ | ボラティリティ | `indicators.realized_volatility` |

### 未実装だが、すぐ足せる

| 手法 | 種類 | 備考 |
|---|---|---|
| ADX / DMI | トレンドの強さ | トレンドの有無を判定するフィルタとして使える |
| ドンチャンチャネル | ブレイクアウト | 過去N本の高値安値の更新。タートルズの中核 |
| オープニングレンジブレイクアウト | ブレイクアウト | 一定時間の値幅を抜けたら追随。24時間市場では「日」の定義を決める必要がある |
| ストキャスティクス | オシレーター | RSIと相関が高い。両方入れても情報は増えにくい |
| CCI / ROC / モメンタム | オシレーター | いずれも価格変化率の変形 |
| ピボットポイント | 水準 | 前日の高値安値終値から算術的に決まる。**引き方に判断が入らない唯一の水準系** |
| VWAP | 出来高加重 | 出来高がOHLCVに含まれるので計算可能。ただし下記の注意あり |
| OBV | 出来高 | 終値の方向で出来高を加減算するだけなので計算可能 |
| **一目均衡表** | 複合 | 転換線・基準線・雲はすべて機械的な計算式。**判断が入るのは解釈だけで、値そのものは一意** |

一目均衡表は「難解」と言われがちだが、**計算そのものは完全に機械的**で、A群に入る。
先行スパンは未来にずらして描画するため先読みに見えるが、
値の計算自体は過去データのみを使う。実装時は描画のずらしと計算を混同しないこと。

### VWAPの注意

VWAPは基準となる期間の取り方で値が変わる。株式なら「その日の寄り付きから」で
自然に決まるが、**24時間動く暗号資産では「1日」の起点を自分で決める必要がある**。
UTC 0時なのか、日本時間0時なのか、あるいはローリング24時間なのかで、
まったく違う指標になる。この選択自体がパラメータであり、
後から都合の良い起点を選べば当てはめになる。

## B. データが足りない手法

定義は一意だが、**OHLCVには含まれない情報**が必要なもの。
この基盤では検証できない。

| 手法 | 必要なデータ | なぜOHLCVでは無理か |
|---|---|---|
| オーダーブック不均衡 | 板情報（L2） | 買い板と売り板の厚みの差。約定していない注文の情報 |
| 板の厚み / 板圧力 | 板情報（L2） | 同上 |
| CVD（累積出来高デルタ） | ティックデータ | 各約定が買い主導か売り主導かの区別。OHLCVの volume は合計だけ |
| 出来高プロファイル | ティックデータ | 価格帯ごとの出来高分布。OHLCVからは近似しかできない |
| 大口注文の検知 | ティック / 板 | 同上 |
| スプレッドの推移 | 板情報 | 気配値の履歴 |

**これらを使いたい場合、まず板データの収集から始める必要があります。**
リアルタイムで取得して自分で保存しない限り、過去分は手に入りません
（取引所が過去の板履歴を提供していることは稀）。

つまり**今日から検証を始めることはできず、数ヶ月データを溜めてからになります。**
最初に手を出す領域としては現実的ではありません。

---

## C. 定義が一意でない手法

同じチャートを見ても、人によって違う答えになるもの。
**「検証できない」のではなく、「検証するには先に定義を機械化する必要がある」。**

| 手法 | どこに判断が入るか |
|---|---|
| サポート / レジスタンス | どの水準を「意識される価格」とみなすか。試された回数・許容誤差の定義が必要 |
| トレンドライン | どの安値とどの安値を結ぶか |
| チャートパターン（三角持ち合い、ヘッドアンドショルダー等） | 「その形である」と判定する基準。許容する歪みの度合い |
| フィボナッチ | 起点となる高値・安値の選び方。**比率の計算自体は機械的だが、どこから引くかで水準が変わる** |
| エリオット波動 | 波のカウント。しかも**後から修正される**ため、事前に検証可能な予測にならない |
| ハーモニックパターン | パターン成立の許容誤差 |

### 機械化すれば A 群に移せる

例えばサポート/レジスタンスは、こう定義すれば一意になります。

> 過去N本の中で、価格が±X%以内に3回以上到達し、そのたびに反転した水準

これなら計算できます。ただし N と X と回数がパラメータとして増えるので、
**当てはめすぎの危険も同時に増えます**。

そして機械化した時点で、それは熟練者が見ている「サポート」と同じものではなくなります。
元の手法の有効性を検証したことにはならない、という点は正直に認識しておくべきです。

### エリオット波動について

波のカウントが後から修正されるという性質は、検証にとって致命的です。
「今は第3波だ」という判断が外れたとき、「実は第1波だった」と数え直せてしまうなら、
その手法は**反証できません**。反証できない主張は、当たったかどうかを事前に定義できず、
バックテストの対象になりません。

これは手法を否定しているのではなく、**この基盤の守備範囲外**だということです。

## 実装の優先順位

検証可能性と、必要な追加作業量で並べるとこうなります。

| 優先 | 内容 | 理由 |
|---|---|---|
| 1 | **ADX / ドンチャン / ピボットポイント** を追加 | A群。追加コストが小さく、既存戦略のフィルタとして機能する |
| 2 | **時間帯フィルタ**（実装済み `SessionFilter`）で既存戦略を絞る | パラメータ1つで検証でき、観測回数が多い |
| 3 | **一目均衡表** を追加 | A群。日本語圏で広く使われており、計算は機械的 |
| 4 | サポレジ・チャートパターンの**機械化を試みる** | C群をA群に移す作業。パラメータが増える点に注意 |
| 5 | 板データの収集を開始する | B群を将来使うための準備。数ヶ月かかる |

---

## 手法を足すときの原則

**指標を足すほど良くなるわけではありません。** むしろ逆です。

- RSIとストキャスティクスは似た情報を持つ。両方入れても情報は増えず、パラメータだけ増える
- パラメータが増えると、過去データに当てはまる組み合わせは必ず見つかる。
  それは発見ではなく当てはめ
- **試した戦略の数を数えておくこと。** 100個試せば、5個は偶然 p<0.05 に見える

新しい手法を足すたびに `validate.check_causality()` を通し、
`walk_forward()` で期間を分けて確認してください。

そして**買い持ちを上回らない限り採用しない**。これが最後の防波堤です。
