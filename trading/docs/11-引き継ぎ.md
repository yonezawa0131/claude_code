## 1. 依頼者が求めていること

**「1日数百円〜数千円の利益を、継続して作る」。**
金額そのものより「小さく始めて、経験を積んで、大きくする」ことを重視している。

想定プラットフォームは **GMOコイン**。元本は30万円前後の想定で会話が進んだ。

## 2. 現在地：**優位性は見つかっていない**

7つの仮説を検定した。うち5つは**事前登録**してから検定している。

| | 仮説 | データ | 結果 |
|---|---|---|---|
| 1〜4 | EMAクロス / RSI逆張り / ドンチャン / 一目均衡表 | 日足944本 | 買い持ちに **−68〜−122 pt** |
| 5 | 日中モメンタム（査読論文） | 1時間足22,656本 | 5基準中4つ不合格 |
| 6 | 銘柄横断モメンタム（査読論文） | 日足944×42銘柄 | 3基準中2つ不合格 |
| 7 | 銘柄横断の反転 | — | **判定不能** |

**6回否定、1回は確かめる手段がなかった。**

5番と6番は質が違う。5番は「無いと言い切れた」（18bpの効果なら**検出確率100%**）。
6番は検出できる最小の効果が年率70.9%で、**文献が報告する水準すら検出できなかった**。
「無い」ではなく「**あっても見つけられない**」に近い。この区別は重要で、
前者は探索を止める根拠になるが、後者はならない。

7番は日本のアルトコイン市場が若すぎて検定できなかった。
2021〜2023年に存在した銘柄は12で、必要な15に満たない。
**前向き検証なら可能**で、2026-08-02 以降のデータが30期（約7か月）たまれば判定できる。
**2027年3月ごろ。**

```bash
python trading/scripts/fetch_universe.py \
    --start 2026-08-02 --end <その日> --out-dir trading/data/universe_fwd
python trading/scripts/run_preregistered_reversal.py --dir trading/data/universe_fwd
```

### この基盤が出した結論（`docs/08`）

目標の難易度は **元本・税制・コスト・優位性** の4つで決まり、
**上から3つは探さなくても手に入る**。

| 元本 | 1日500円に必要な粗利(年率) | 判定 |
|---|---|---|
| 30万円 | 135.2% | 現実的でない |
| **300万円** | **13.5%** | **買い持ちの実績17.9%で届く** |

**主たる手段は優位性ではなく元本だった、というのが理論の答えになる。**
ただしこれは「暗号資産に300万円を置くべきか」とは別の問題で、
買い持ちの実績には**最大50.2%の下落**が含まれる。そこは依頼者の判断領域。

## 3. 執行基盤：どこまで確かめたか

`run_live.py` は取引所から現在地を読み、目標との差分を注文にする。
**既定はペーパー。** 本番は `--live` を明示し、さらに関門を全部通ったときだけ動く。

### 確定していること

2026年8月4日、GMOコインの実口座に対して `--check-connection` を実行した。

- **署名の組み立ては取引所に受理された。**
  鍵・時刻（ミリ秒）・HMAC-SHA256・ヘッダ名（`API-KEY` / `API-TIMESTAMP` / `API-SIGN`）・
  署名するパスから `/private` を除くこと、いずれも正しい

### 確定していないこと

- **資産応答の解釈。** 口座が空だったため応答も空で、
  「資産がない」と「解釈を間違えて何も拾えていない」が区別できない。
  **入金して、金額が取引所の画面と一致して、はじめて確定する**
- **発注応答の解釈。** 一度も注文を出していない
- **`BitbankBroker` は全体が未検証。** 一度も実物に当てていない

だから両ブローカーとも `unverified=True` のまま。**外すのは、
最小額の注文を1回出して取引所の画面と突き合わせてからにすること。**

### 送る前に見つけた不具合（記録として）

接続確認の出力で、`size` が `'1e-05'` になっていた。
GMOのBTC現物の最小注文数量は 0.00001 なので、**最小数量で出すたびに指数表記になる**。
送っていれば「署名は通るのに注文だけ弾かれる」となり、署名を疑って探し回っていた。
`plain_decimal()` で修正済み。

**なお実際の最小数量 0.00001 は、二次情報にあった 0.0001 の10分の1だった。**
注文ルールを `/public/v1/symbols` から実行時に読む設計にしていたので助かった。
**ここを記憶で埋め直さないこと。**

## 4. 触ってはいけない安全装置

**どれも、緩めれば静かに動くようになる。** 動くようになったこと自体を
「進捗」と読み違えないこと。

### 4.1 APIキーに出金権限を付けない

取引権限だけで足りる。付けなければ、鍵が漏れても**動かされるのは板の上だけ**になる。

### 4.2 検証記録がなければ本番で発注しない（`guards.check`）

```
[未検証] 戦略「equal_weight_btc」の検証記録がありません。
```

**合格記録のある戦略は現時点で存在しない。** つまりこの関門は今、
すべての戦略を止めている。**これは不具合ではない。**

実データで測った5戦略は、元本30万円で平均11.5万円を失う成績だった。
自動化していれば、その損失は取りこぼしなく実現していた。
`validation.json` を手で書いて通すのは、**測っていないものを測ったことにする**行為になる。

### 4.3 ペーパーが既定

`--live` は明示が要る。ペーパーでも指値は**価格が届くまで板に残る**。
出した瞬間に約定させると利益が無から湧く（実際に一度そうなり、
30万円が1回の売買で300,150円になった）。

### 4.4 GMOでは `BTC` が現物、`BTC_JPY` はレバレッジ

取り違えると、現物を買ったつもりで建玉を持ち、1日0.04%を払い続ける。
`GmoBroker` は対応表にある現物銘柄しか受け付けない。

照合は**大文字のまま完全一致**でやること。`upper()` してから照合すると、
内部表記の `btc_jpy` が `BTC_JPY` に化けて全銘柄が拒否される（一度そうなった）。

### 4.5 記録をリポジトリに入れない

`trading/data/journal.jsonl` には**残高と資産額が入る**。
`.gitignore` 済みだが、`git add -f` で入れないこと。

### 4.6 事後に見つけた仮説を、同じデータで検証しない

`run_preregistered_reversal.py` は、発見に使った期間
（2024-01-01〜2026-08-01）を渡されたら**実行を拒否する**。
この拒否を外さないこと。

## 6. この基盤の一番大事な性質

**「何も見つからなかった」と「壊れていて何も見つけられない」は、出力が同じになる。**

だから陽性対照（答えを埋め込んだデータ）を先に置いてある。
`--regime intraday` で検出できることを確認済みなので、
空振りを「壊れていた」と取り違えずに済む。

この対照は、作った直後に実装のバグを2つ捕まえた。

同じ理由で、**この記録には都合の悪い結果と自分の誤りがそのまま残してある**。
`docs/02` `09` `10` には、前任が踏んだ間違いが理由つきで書いてある。
消さないこと。**同じ間違いを二度踏まないための唯一の資産になる。**

そして最後に、これが一番重い。

> **確かめられない仮説は、資金を入れる根拠にならない。**
>
> 「効果があるかもしれない」と「効果があると確かめた」の差が、
> 資金を入れてよいかどうかを分ける。前者で入れるなら、それは検証ではなく賭けになる。
