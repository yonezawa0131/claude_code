# 陽性対照と日中モメンタム

## なぜ陽性対照が要るのか

検出器を実データに向ける前に、確かめておくべきことがある。

**「何も見つからなかった」と「壊れていて何も見つけられない」は、出力が同じ。**

この基盤にはもともと陰性対照（`random` レジーム＝優位性のないランダムウォーク）があった。
そこで利益が出ればエンジンのバグだと分かる。しかしこれだけでは足りない。

```python
def generate(self, df):
    return _empty_signals(df.index)   # 常にノーポジ
```

この空実装は、陰性対照を**必ず**通る。取引しないので利益も損失も出ない。
つまり陰性対照は「壊れていないこと」を保証しない。

だから逆側の対照が要る。**答えが分かっているデータで、正解を出せるか。**
医学の陽性対照（positive control）と同じ役割になる。

## 埋め込んだもの

`make_synthetic.py` に `intraday` レジームを追加した。
ランダムウォークに、**日中モメンタムだけ**を埋め込む。

```
r[セッション最終バー] = beta × r[セッション初バー] + ノイズ
```

- 加える量の期待値は0なので、**系列全体のドリフトは生まれない**。買い持ちでは取れない
- トレンドもレンジもない。取れるのは「セッション内のどこにいるか」を見た場合だけ
- `beta` で強さを連続的に変えられる。**`beta=0` にすると `random` と同じ性質になる**

最後の点が重要で、陽性と陰性で**同じ乱数シードを使える**。
2本のデータの違いはパターンの有無だけになるので、成績の差を他の要因で説明できなくなる。

効果の大きさは事前に計算できる。ロングだけ取る場合、初バーが上げたときの
最終バーの期待リターンは `beta × sigma × sqrt(2/π)`。
`beta=1.0, sigma=0.006` なら **+0.479%**。往復コスト0.18%を引いても残る。

```bash
python scripts/make_synthetic.py --bars 5000 --seed 7 --regime intraday \
  --intraday-beta 1.0 --out data/synthetic_intraday.csv
```

## 結果

元本30万円・GMOコイン取引所のコスト（Taker）・5000本（1時間足で約208セッション）。

### 陽性対照で検出できたか

| データ | 総リターン | 買い持ち | 取引 | 勝率 | 最大DD |
|---|---|---|---|---|---|
| `beta=1.0`（パターンあり） | **+47.96%** | -35.10% | 108 | 68.5% | -3.3% |
| `beta=0.0`（同シード・パターンなし） | -17.12% | -43.63% | 108 | 40.7% | -20.9% |

**取引回数が両方108回**であることに注目したい。
戦略は同じだけ動いていて、**違うのは動いた先に何かがあったかどうかだけ**。

コストを外すと `beta=0.0` の成績は **+0.66%** になる。ほぼゼロ。
つまり −17.12% の正体は全額コストで、エンジンは利益も損失も作っていない。

### 埋め込んだ量と検出した量が対応するか

`beta` を上げると成績も上がる（コストゼロ、`test_stronger_pattern_gives_a_larger_result`）。
連動しないなら、検出しているのはパターンではない別の何かだったことになる。

### 他の戦略はどうか

同じ `intraday` データに全戦略を当てた結果：

| 戦略 | 総リターン | 取引 |
|---|---|---|
| **日中モメンタム** | **+43.71%** | 108 |
| ランダム（対照群） | -17.23% | 57 |
| 買い持ち | -35.22% | 1 |
| RSI逆張り | -52.84% | 106 |
| ドンチャンブレイクアウト | -57.84% | 142 |
| 一目均衡表 | -71.13% | 224 |
| EMAクロス+ATR損切り | -87.11% | 351 |

**埋め込んだパターンを取れたのは、それを狙って書いた戦略だけだった。**
データが単に「儲かりやすい」わけではないことの確認になる。

逆に、日中モメンタムは他の4レジーム（trend / range / mixed / random）で
すべて負けている（-17% 〜 -20%）。**無いところで見つけたと言い出さない。**

### ウォークフォワード

期間を5分割すると5期間すべてプラス（平均 +7.55%、標準偏差 5.71%）。

**ただしこの検証は検出力が足りていない。**
5000本を5分割すると各期間18〜23回の取引しかなく、
`metrics.evaluate()` が警告を出す30回の基準を下回る。
期間ごとの成績がノイズに埋もれるので、**並びを傾向として読んではいけない**。

実際、この本数では「優位性が一定のデータ」と「消えていくデータ」を
区別できなかった。区別できるようになるのは、期間ごとに
50回以上の取引が確保できる本数（20000本を6分割）から。

→ `docs/04-検証器の検証と検出限界.md`。
ウォークフォワード検証は現在、期間ごとの取引数が足りないときに警告を出す。

## 見つけて直した実装の誤り

陽性対照は、作った直後に**自分の実装のバグを2つ**捕まえた。

### 1. 執行が1本ずれていた

エンジンは `direction[t]` を**バー t+1 の始値**で執行する。
終盤の窓にそのまま `direction` を立てると、実際に持つのは
**次のセッションの頭**になる。狙ったバーを持てていない。

この取り違えは気づきにくい。**成績自体は出てしまう**からで、
陽性対照が無ければ「効いている」と読んで終わっていた。

→ 持ちたいバーの1本前に立てるよう修正。
`test_holds_the_last_bar_of_the_session_not_the_first_of_the_next` が位置で直接検査する。

### 2. index の分解能に依存していた

セッションの区切りを `DatetimeIndex.asi8`（整数のタイムスタンプ）から計算していた。
pandas はデータによって `datetime64[ns]` にも `datetime64[us]` にもなるので、
**同じデータを読み込み方だけ変えると結果が変わる**状態だった。
実際、この環境では `[us]` になり、検出はゼロ件だった。

→ 必ず秒に直してから割るよう修正。
`test_index_resolution_does_not_change_the_answer` が ns / us / ms で一致を確認する。

セッションの基点も、最初の行ではなく**1970年基点の絶対時刻**に変えた。
最初の行を基点にすると、データの切り出し位置が変わるだけで区切りが動いてしまう。

## 日中モメンタムそのものについて

### 根拠

**Shen, Urquhart & Wang (2022, _Financial Review_)** が、
ビットコインで**セッション冒頭の値動きが終盤の値動きを予測する**ことを報告した。
もとは **Gao, Han, Li & Zhou (2018)** が S&P500 ETF で見つけた現象。

ビットコインは24時間動くので株式のような寄り付き・引けがない。
原論文は**出来高をセッションの代理変数**として使った。
ここでは扱いやすさを優先して時計で区切っている（既定はUTC 0時からの24時間）。

**この時間軸で、ビットコインを対象に、査読論文の裏付けがある数少ない仮説。**
ただし論文が見つけたのは特定の標本期間の現象で、今も続いている保証はない。

### この実装の性質

- 1セッションに1往復しかしない。**取引回数が構造的に少ない**
- 中間の時間帯はノーポジ。市場に晒される時間が短い
- 測る窓と持つ窓が重なる設定は**例外を投げて拒否する**（同じバーを見て賭けることになるため）

取引回数の少なさは、この基盤が最も重視する改善策（`docs/02` の項目1）と方向が一致する。

### 警戒すべきこと

**セッションの区切り自体がパラメータである。**
`session_start_hour`、`session_hours`、`entry_bars`、`exit_bars`、`threshold`。
これらを変えて試し、良かった組み合わせを後から選べば、それは当てはめになる。

試した回数を数えておくこと。`growth.expected_max_sharpe(試行数, 観測数)` が、
**優位性ゼロでも偶然そこまで到達しうるシャープ**を返す。
観測値がそれを超えていなければ、その数字は「たくさん試したから出てきた」だけになる。

## この対照が保証すること／しないこと

**保証する**
- 検出器が、存在するパターンを、コスト控除後に検出できること
- 検出器が、存在しないパターンを見つけたと言わないこと
- 「見つからなかった」という結果を、壊れていないコードの出力として読めること

**保証しない**
- 実データにこのパターンがあるかどうか。**それはまだ測っていない**
- 弱い信号を検出できるか。ここで埋めた `beta=1.0` は「検出できて当然」の強さにしてある。
  実際の効果がこれより弱ければ、コストに埋もれて検出できない可能性がある
- 実際の約定。1セッション1往復とはいえ、指値が約定するかは過去のOHLCVからは分からない

最後の点は特に重い。**この戦略が実データで通用するかは、まだ何も分かっていない。**
分かったのは、測る道具のほうが壊れていないということだけ。
