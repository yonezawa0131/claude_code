# 試行数を数える

`README` に最初から「**測れないこと**」として書いてあった項目がある。

> 何十個も戦略を試したときの「たまたま良く見えた1つ」を見分けること。
> 100個試せば5個は偶然 p<0.05 に見える。**試した数を数えておくこと**

数えるための道具（`growth.expected_max_sharpe`）は置いてあった。
**式は正しかった。単位が合っていなかった。**

---

## 何が起きていたか

`expected_max_sharpe(n_trials, n_observations)` は、
優位性がまったくない戦略を N 個試したときに
最良のものが示すシャープレシオの期待値を返す。

Bailey & López de Prado の式で、標準誤差 `1/sqrt(n)` に
順序統計量の係数を掛けたもの。**これは「1バーあたり」のシャープに対する値。**

一方 `metrics.sharpe_ratio()` は**年率化した**シャープを返す。
1時間足なら `sqrt(8766) = 93.6` 倍。

この2つを比べていた。

```
試した戦略 100 個 → 偶然でも届く水準 0.04 / 観測 5.12 → 意味あり
```

閾値 0.04 は、年率シャープと比べる数字としては無意味に小さい。
**この状態では、何を渡しても合格する。** 安全装置として一切機能していなかった。

---

## 実測でどうだったか

### 式そのものは正しい

優位性ゼロのリターン系列を N 本作り、最良のシャープを取る。1万回反復。

| 試行数 | 実測（1バーあたり） | 式 |
|---|---|---|
| 5 | 0.01659 | 0.01687 |
| 20 | 0.02635 | 0.02688 |
| 100 | 0.03532 | 0.03579 |

一致する。式の実装に誤りはない。

### 実際のバックテストではどうなるか

優位性ゼロのランダムウォーク（15本）に、優位性ゼロの戦略を40個。
コストはゼロにして、多重検定の効果だけを取り出した。

| 試行数 | 実測の最大シャープ（平均） | 実測の最悪 | 年率化した式 | **当時の式** |
|---|---|---|---|---|
| 5 | 1.54 | 2.75 | 1.58 | 0.017 |
| 10 | 1.83 | 2.75 | 2.08 | 0.022 |
| 20 | 2.29 | 4.46 | 2.52 | 0.027 |
| 40 | 2.42 | 4.46 | 2.90 | 0.031 |

**40個試せば、優位性ゼロでも年率シャープ 2.42 が平均的に出る。悪い回では 4.46。**

年率化した式はこれとよく合う。当時の式（0.031）はまったく合わない。

なお単一戦略の年率シャープの標準偏差は実測 1.60、理論値 `sqrt(8766/5000) = 1.32`。
実測のほうが少し大きい。バックテストの損益は独立同分布ではないため、
**式はやや楽観側**に出ると考えておくのが安全。

### パラメータ探索の場合（試行が相関する）

同じ戦略のパラメータを振るのが、実際にやることに近い。
`IntradayMomentum` の（セッション区切り × 測る本数 × 持つ本数 × 閾値）48通り。

| 試行数 | 実測の最大（平均） | 年率化した式 |
|---|---|---|
| 5 | 1.21 | 1.58 |
| 12 | 1.57 | 2.20 |
| 24 | 2.04 | 2.62 |
| 48 | 2.61 | 2.99 |

**すべて式のほうが厳しい側**。試行が相関していると、独立に N 回引くより
最大値は小さくなるため。式は独立を仮定するので、この場合は保守的になる。安全な方向。

（試行どうしの相関は平均 +0.06 と低かった。
セッションの区切りを変えると取るトレードがほぼ入れ替わるので、
パラメータ探索でも実質的に独立に近い試行になっていた。）

## 直したこと

### 単位を引数にした

```python
expected_max_sharpe(n_trials, n_observations, periods_per_year=1.0)
```

既定の 1.0 は1バーあたり。年率シャープと比べるなら 1時間足で 8766、日足で 365。

### 単位を取り違えられない経路を作った

素の float を渡す API がある限り、同じ間違いは再発する。
**Report は自分の年率化係数と観測数を知っている**ので、そちらを使う。

```python
from trading.src.metrics import multiple_testing_report
print(multiple_testing_report(report, n_trials=48))
```

`Report` に `periods_per_year` と `n_observations` を持たせた。

### `--compare-all` に自動で組み込んだ

比較した戦略の本数が、そのまま試行数になる。数え忘れが起きない。

```
最もシャープが高かったのは「ランダム（対照群）」でした。

試行数を考慮した判定
  試した戦略・設定の数 : 7
  観測数               : 4999 本
  観測したシャープ     : -0.87（年率）
  優位性ゼロでも到達しうる水準: 1.84

  → **この成績は、たくさん試したことだけで説明がつきます。**
```

同じ判定を陽性対照データにかけると、観測 5.12 が閾値 1.84 を超えて通る。
**本物は通り、偶然は弾かれる。**

### 試行数1を黙って通さない

既定で `n_trials=1` を渡されると閾値が0になり、何でも合格する。
そのときは「実際に試した数を数えて渡さないと、この判定は意味を持ちません」と明示する。

---

## 使うときの注意

**n_trials は、捨てた分も含めた総数。**

採用した1個ではない。パラメータを振った回数、
指標を差し替えた回数、期間を変えて試した回数、すべて足す。
`--compare-all` が数えるのは**その1回の比較で回した本数だけ**なので、
何度も回したならその回数を掛ける。

数えるのが面倒なほど試したなら、それ自体が答えになっている。

**この判定を通っても、それは「偶然では説明しにくい」以上のことを意味しない。**
将来も続くことの根拠にはならない。

---

## 残っている前提

- 式は**試行が独立**であることを仮定する。相関していれば保守的に出る（測定済み）
- バックテストの損益は独立同分布ではないので、式はやや楽観側に出る（実測 1.60 vs 理論 1.32）
- コストゼロで測った。実際にはすべての戦略が負のドリフトを持つため、
  最大シャープの水準は下がる。**この閾値は厳しめの側**
