# バックテスト基盤

ビットコインの短期売買戦略に**優位性があるかどうかを、資金を入れる前に測る**ための道具。

儲かる戦略は入っていない。入っているのは、儲かるかどうかを**正直に測る仕組み**だけ。

## なぜこれを先に作るのか

短期売買で最初に必要なのは戦略ではなく、**戦略が本物かを見分ける手段**。
バックテストは簡単に嘘をつくので、嘘をつかせない仕組みを先に用意する。

このエンジンが対策している、バックテストが実運用より良く見える典型的な原因：

| 原因 | 対策 |
|---|---|
| 先読み（未来のデータで過去を判断） | シグナルは**次のバーの始値**で執行。`check_causality()` で機械的に検査 |
| コストの過小評価 | 全約定に手数料・スプレッド・滑りを乗せる |
| 同一バー内で損切りと利確の両方に触れたとき有利側を採用 | **常に損切りが先**とみなす |
| 買い持ちと比較しない | 全レポートに買い持ちを併記。下回れば明示 |
| 取引回数が少なすぎるのに結論を出す | 30回未満で警告 |

## 使い方

```bash
# 環境（このリポジトリのルートで）
python3 -m venv .venv-trading
.venv-trading/bin/pip install pandas numpy

# エンジンが正しいことを確認する（最初に必ず）
.venv-trading/bin/python trading/tests/test_engine.py

# 合成データで挙動を見る（ネットワーク不要）
.venv-trading/bin/python trading/scripts/make_synthetic.py \
  --bars 5000 --seed 42 --regime mixed --out trading/data/synthetic.csv

.venv-trading/bin/python trading/run_backtest.py \
  --data trading/data/synthetic.csv --compare-all

# 「1日いくら」が元本に対して何%なのかを見る
.venv-trading/bin/python trading/run_backtest.py --show-required-return
```

### 実データで測る

**取得スクリプトは自分のPCで実行すること。** 開発環境からは取引所APIに到達できない。

```bash
.venv-trading/bin/python trading/scripts/fetch_ohlcv.py \
  --exchange bitbank --pair btc_jpy --interval 1hour \
  --start 2024-01-01 --end 2026-08-01 --out trading/data/btc_jpy_1hour.csv

.venv-trading/bin/python trading/run_backtest.py \
  --data trading/data/btc_jpy_1hour.csv --strategy ema_atr \
  --cost gmo --capital 300000 --walk-forward 6
```

## 合成データで分かったこと

同梱の戦略を4つのレジームで回した結果（元本30万円・GMOコイン取引所のコスト）。

| | トレンド相場 | レンジ相場 | ランダムウォーク |
|---|---|---|---|
| 買い持ち | **+1244%** | -1.6% | -45.1% |
| EMAクロス+ATR損切り | +85%（367回） | **-94%**（390回） | **-90%**（367回） |
| RSI逆張り | +1.7%（14回） | **+16.6%**（50回） | -62%（110回） |

読み取れること：

- **すべてのレジームで勝つ戦略はなかった。** RSI逆張りはレンジで勝ち、トレンドとランダムで負けた
- **強いトレンドでは買い持ちに勝てない。** トレンド追随戦略ですら、損切りと再エントリーを繰り返して1244%に対し85%だった
- **取引回数と損失が相関する。** ランダムウォークでは367回取引した戦略が-90%、57回が-17%、1回（買い持ち）が-45%

3つ目が一番重い。**優位性のない相場では、動けば動くほど負ける。** これがコストの正体。

## 何が測れて、何が測れないか

**測れる**
- ある戦略が、ある期間・あるコスト条件で、買い持ちを上回ったか
- コストが利益をどれだけ食うか
- 期間を分けても通用するか（ウォークフォワード）
- その戦略が先読みしていないか

**測れない**
- 将来も通用するか。過去に効いた戦略が今後も効く保証はない
- 何十個も戦略を試したときの「たまたま良く見えた1つ」を見分けること。
  100個試せば5個は偶然 p<0.05 に見える。**試した数を数えておくこと**
- 実際の約定。指値が本当に約定するか、板が薄いときにいくら滑るかは、
  過去のOHLCVからは分からない

## 構成

```
trading/
  src/
    costs.py        手数料・スプレッド・滑りのモデル（国内取引所の実数値）
    indicators.py   SMA/EMA/RSI/ATR/MACD/ボリンジャー。すべて因果的
    strategy.py     戦略。買い持ち・ランダム対照群・EMAクロス・RSI逆張り
    backtest.py     エンジン本体
    metrics.py      評価（買い持ちベンチマーク込み）
    validate.py     先読み検査・ウォークフォワード・必要リターン表
  scripts/
    fetch_ohlcv.py    実データ取得（手元で実行）
    make_synthetic.py 合成データ生成
  tests/
    test_engine.py    エンジンの自己検証（18件）
  run_backtest.py     CLI
```

## 数字についての注意

`costs.py` の料率は調査時点（2026年8月）の公開情報。
**bitbank の Taker 手数料は確認できておらず、仮の値が入っている**（`unverified=True` で警告が出る）。
口座を開いたら管理画面の実数値で上書きすること。往復0.05%の差が、
日に数回転する戦略の損益を大きく変える。

## 制度面のメモ

- 国内の個人向け暗号資産証拠金取引は**レバレッジ2倍が上限**（2020年5月施行の内閣府令）。
  `BacktestConfig(leverage=...)` は2を超えると例外を投げる
- **現物ではショートできない。** ショート戦略には証拠金取引口座が必要。既定では無効
- 2026年8月現在、売買益は**雑所得・総合課税**（最高約55%）。損失の繰越控除は不可。
  分離課税（20.315%）への移行は決まっているが、適用は早くて2028年1月の見込み
- **販売所形式は片道3〜6%。** `--cost dealer` で試せるが、往復9%は短期売買では取り返せない。
  必ず取引所（板取引）形式を使うこと

## 次にやること

1. `tests/test_engine.py` を通す（エンジンを信じてよいか確認）
2. `--show-required-return` で、自分の元本だと1日いくらが何%にあたるかを見る
3. 手元で実データを取得する
4. `--compare-all --walk-forward 6` で、買い持ちを安定して上回る戦略があるか探す
5. **どの期間でも買い持ちを上回る戦略が見つからなければ、そこで止める。**
   見つからないと分かることが、この基盤の一番の成果になりうる
