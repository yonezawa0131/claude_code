# バックテスト基盤

ビットコインの短期売買戦略に**優位性があるかどうかを、資金を入れる前に測る**ための道具。

儲かる戦略は入っていない。入っているのは、儲かるかどうかを**正直に測る仕組み**だけ。

## なぜこれを先に作るのか

短期売買で最初に必要なのは戦略ではなく、**戦略が本物かを見分ける手段**。
バックテストは簡単に嘘をつくので、嘘をつかせない仕組みを先に用意する。

このエンジンが対策している、バックテストが実運用より良く見える典型的な原因：

| 原因 | 対策 |
|---|---|
| 先読み（未来のデータで過去を判断） | シグナルは**次のバーの始値**で執行。`check_causality()` で機械的に検査 |
| コストの過小評価 | 全約定に手数料・スプレッド・滑りを乗せる |
| 同一バー内で損切りと利確の両方に触れたとき有利側を採用 | **常に損切りが先**とみなす |
| 買い持ちと比較しない | 全レポートに買い持ちを併記。下回れば明示 |
| 取引回数が少なすぎるのに結論を出す | 30回未満で警告 |
| 壊れていて何も見つけられないのを「何も無かった」と読む | **陽性対照**（既知のパターンを埋め込んだデータ）で検出能力を先に確認 |
| 優位性が既に消えているのに、過去の利益で平均がプラスに見える | ウォークフォワードで**後半と前半を比較**。勝った期間の数だけでは弾けない |
| たくさん試して、たまたま良かった1つを実力と読む | `--compare-all` が**試行数を考慮した閾値**を出す。40個試せば優位性ゼロでも年率シャープ2.4は出る |
| 指値が必ず約定する前提で計算する | 高値安値から**約定判定**。損切りは常に成行。未約定回数を警告に出す |
| 上げ相場に居合わせただけの成績を、実力と読む | **ローテーション検定**。同じ売買パターンをでたらめな時点に置いて比べる |
| 高ベータ銘柄を選んだだけの成績を、予測力と読む | 銘柄横断では**上位−下位**を本体にする。**無作為割当**の対照も置く |
| 目標の難易度を、税引前で見積もる | `goal.py` が**税制込み**で必要な粗利を出す。制度で2.22倍変わる |
| 検証していない戦略を自動で動かす | `run_live.py` は**合格記録がなければ本番モードで発注しない** |
| 記憶と実際の保有がずれる | 毎回**取引所から読み直す**。差分だけ出すので二重発注も起きない |
| ペーパーで指値が必ず約定して、利益が湧く | 指値は**価格が届くまで板に残る**。出しただけでは総資産が動かない |
| 逆に、瞬間値で見て「約定しなかった」と嘘をつく | **注文を置いた時刻から**の値動きの幅で判定。一度でも触れていれば約定 |
| 指値で粘りすぎて、目標にたどり着けない | 3回届かなければ**成行に切り替える**。記録から数えるので記憶は不要 |
| 前後半に分けたつもりが、別の週を測っている | 期間を切り直さず、**同じ検定の結果を分ける**。合計は必ず全期間に一致 |
| 1期の暴落だけで決まった平均を、傾向と読む | 中央値と**最大の1期を除いた平均**を併記。符号が変わればそう言う |
| 事後に見つけた仮説を、同じデータで検証する | `run_preregistered_reversal.py` は**発見に使った期間を渡されたら拒否する** |

## 使い方

**すべて、リポジトリのルート（`trading/` が見えるディレクトリ）で実行すること。**
ホームディレクトリで叩くと `No such file or directory` になる。

```bash
# 1. リポジトリを取得して、そのディレクトリに入る
git clone https://github.com/yonezawa0131/claude_code.git
cd claude_code
git checkout claude/affiliate-income-site-wmo11w

# 2. 環境を作る（pytest も入れること。テストの大半は pytest で動く）
python3 -m venv .venv-trading
.venv-trading/bin/pip install pandas numpy pytest

# 3. エンジンが正しいことを確認する（最初に必ず）
.venv-trading/bin/python -m pytest trading/tests -q

# 4. 合成データで挙動を見る（ネットワーク不要）
.venv-trading/bin/python trading/scripts/make_synthetic.py \
  --bars 5000 --seed 42 --regime mixed --out trading/data/synthetic.csv

.venv-trading/bin/python trading/run_backtest.py \
  --data trading/data/synthetic.csv --compare-all

# 「1日いくら」が元本に対して何%なのかを見る
.venv-trading/bin/python trading/run_backtest.py --show-required-return
```

Python は 3.9 以上で動く（3.9 で構文・注釈の互換性を確認済み）。

pytest を入れたくない場合、エンジン本体の18件だけは単体で走る。

```bash
.venv-trading/bin/python trading/tests/test_engine.py
```

### 実データで測る

**取得スクリプトは自分のPCで実行すること。** 開発環境からは取引所APIに到達できない。

```bash
# ① まず疎通を確認する（リクエスト1回。数秒）
.venv-trading/bin/python trading/scripts/fetch_ohlcv.py \
  --exchange bitbank --pair btc_jpy --diagnose

# ② 短い足種で通し確認（年単位なので3回で終わる）
.venv-trading/bin/python trading/scripts/fetch_ohlcv.py \
  --exchange bitbank --pair btc_jpy --interval 1day \
  --start 2024-01-01 --end 2026-08-01 --out trading/data/btc_jpy_1day.csv

# ③ 本番。1hour が日単位でしか取れない場合は約950回のリクエストになる。
#    スクリプトが最初に形式を確かめて、回数と所要時間の目安を表示する
.venv-trading/bin/python trading/scripts/fetch_ohlcv.py \
  --exchange bitbank --pair btc_jpy --interval 1hour \
  --start 2024-01-01 --end 2026-08-01 --out trading/data/btc_jpy_1hour.csv

# 全戦略を比較し、最も良かったものを期間分割＋ローテーション検定で調べる
.venv-trading/bin/python trading/run_backtest.py \
  --data trading/data/btc_jpy_1hour.csv \
  --compare-all --cost gmo --capital 300000 --walk-forward 6 --null-runs 200

# 事前登録した検定（条件は固定。パラメータは渡せない）
.venv-trading/bin/python trading/scripts/run_preregistered.py \
  --data trading/data/btc_jpy_1hour.csv
```

データ取得元（bitbank）と、コストの前提（`--cost gmo`）は別で構わない。
価格系列はどちらの取引所でもほぼ同じで、変わるのは手数料とスプレッドだから。
**執行するつもりの取引所のコストを指定すること。**

## 実データで分かったこと

BTC/JPY・bitbank から取得・GMOコイン取引所の実料率・元本30万円・成行。

| データ | 戦略 | 結果 |
|---|---|---|
| 日足 944本（2024-01〜2026-08） | EMAクロス / RSI逆張り / ドンチャン / 一目均衡表 | 全滅。買い持ちに **−68 〜 −122 pt** |
| 同上 | ランダム（対照群） | 見かけ上勝った（+2.06pt）が、**2つの検定が否定** |
| 1時間足 22,656本 | 日中モメンタム（**事前登録**） | 5基準中4つ不合格。6期間すべてマイナス |
| 日足 944本 × 42銘柄 | 銘柄横断モメンタム（**事前登録**） | 3基準中2つ不合格。上位群が下位群に負けた |
| 日足 × 12銘柄（2021〜2023） | 銘柄横断の反転（**事前登録**） | **判定不能。** 当時の上場は12銘柄で、検定に必要な15に満たない |

この期間、ビットコインは **+64.4%** 上昇し、途中で **−50.2%** 下げた。
**4つの古典的戦略は、その上げ相場で全部負けた。**

日中モメンタムについては、負けた原因まで切り分けた。
コストを全部外してもマイナスで、シグナルそのものに予測力がなかった。

```
セッション冒頭が上げた日の、終盤バーの平均: -3.76 bp
セッション冒頭が下げた日の、終盤バーの平均: -2.63 bp
差                                        : -1.13 bp （95%CI: -6.58 〜 +4.33）
成行で必要な水準                            : 18.00 bp
```

**18 bp の効果があれば検出できる確率は100%。** 見つからなかったのは
検出力不足ではない。詳細は `docs/07-事前登録した検定の結果.md`。

## 合成データで分かったこと

同梱の戦略を5つのレジームで回した結果（元本30万円・GMOコイン取引所のコスト）。

| | トレンド相場 | レンジ相場 | ランダムウォーク | 日中モメンタム |
|---|---|---|---|---|
| 買い持ち | **+1244%** | -1.6% | -45.1% | -35.2% |
| EMAクロス+ATR損切り | +85%（367回） | **-94%**（390回） | **-90%**（367回） | -87%（351回） |
| RSI逆張り | +1.7%（14回） | **+16.6%**（50回） | -62%（110回） | -53%（106回） |
| 日中モメンタム | -17%（106回） | -19%（96回） | -20%（90回） | **+44%（108回）** |

読み取れること：

- **すべてのレジームで勝つ戦略はなかった。** RSI逆張りはレンジで勝ち、トレンドとランダムで負けた
- **強いトレンドでは買い持ちに勝てない。** トレンド追随戦略ですら、損切りと再エントリーを繰り返して1244%に対し85%だった
- **取引回数と損失が相関する。** ランダムウォークでは367回取引した戦略が-90%、57回が-17%、1回（買い持ち）が-45%

3つ目が一番重い。**優位性のない相場では、動けば動くほど負ける。** これがコストの正体。

### 陽性対照

一番右の列は**答えを埋め込んだデータ**（`--regime intraday`）。
セッション初バーのリターンが最終バーに乗るよう作ってあり、
**それを狙って書いた戦略だけが取れる**。他の6戦略はすべて負けている。

なぜこれが要るか：**「何も見つからなかった」と「壊れていて何も見つけられない」は出力が同じ**。
陰性対照（ランダムウォーク）だけでは、常にノーポジを返す空実装すら合格してしまう。

この対照は作った直後に実装のバグを2つ捕まえた（執行の1本ずれ、index分解能への依存）。
詳細は `docs/03-陽性対照と日中モメンタム.md`。

### 検出できる信号の下限

同じ仕組みで、埋め込む強さを変えて「どこまで弱い信号を拾えるか」を測れる。

| 執行 | 往復コスト | 必要な粗利/トレード |
|---|---|---|
| 成行（Taker） | 0.180% | **18.0 bp** |
| 指値（Maker・必ず約定する前提） | 0.020% | **2.0 bp** |

成行で回す限り、18bp未満の優位性は存在しても取れない。
詳細は `docs/04-検証器の検証と検出限界.md`。

**ただしこの9倍差は、指値が必ず約定する前提の上限値。**
約定判定を入れて測り直すと、**戦略によっては指値のほうが悪くなる**。

| 戦略 | 成行 | 指値（必ず約定） | 指値（約定判定あり） |
|---|---|---|---|
| EMAクロス（1,404回・やり直せる） | +6,844% | +25,416% | **+12,192%** |
| 日中モメンタム（1セッション1回きり） | +310% | +701% | **+142%** |

分かれ目は「約定しなかったときにやり直せるか」。
一度きりの機会を狙う戦略では、取り逃しのほうが手数料の節約より高くつく。
しかも取り逃す機会は**平均して2倍良い機会**だった（逆選択）。
測定結果は `docs/02` の項目2。

## 何が測れて、何が測れないか

**測れる**
- ある戦略が、ある期間・あるコスト条件で、買い持ちを上回ったか
- コストが利益をどれだけ食うか
- 期間を分けても通用するか（ウォークフォワード）
- その戦略が先読みしていないか

- 何十個も戦略を試したときの「たまたま良く見えた1つ」かどうか。
  `--compare-all` が試行数を考慮した閾値を自動で出す
  （**ただし数えるのは1回の比較ぶんだけ**。何度も回したなら自分で足すこと）

- 指値が約定したかの**目安**。高値安値が指値を抜けたかで判定する
  （板の順番が分からないので、同値までなら約定しない側に倒している）

**測れない**
- 将来も通用するか。過去に効いた戦略が今後も効く保証はない
- 板の厚み、バー内の時間順序、部分約定。
  自分の注文が板を動かす影響も、安値がバーの前半に来たか後半かも分からない
- 深い指値の値段改善。約定率だけ下がる形にしてあるので、**保守側にずれている**

## 取引所につなぐ（発注はしない）

`BitbankBroker` は `unverified=True` のまま置いてある。この開発環境から
取引所に到達できないため、署名の組み立ても応答の解釈も
**実物に対して一度も確かめていない**。

確かめるのに発注は要らない。署名の仕組み（nonce・HMAC・ヘッダ名）は
読み取りと発注で共通なので、**読むだけの呼び出しが通れば鍵と署名は確定する**。

```bash
# APIキーは【取引権限だけ】。**出金権限は絶対に付けないこと**
BITBANK_API_KEY=... BITBANK_API_SECRET=... \
    .venv-trading/bin/python trading/run_live.py --check-connection
```

出るもの:

1. 公開APIで価格が取れるか（署名なし）
2. 私設APIで資産が読めるか（署名あり）→ **取引所の画面と突き合わせること**
3. 最小数量で発注するときの本文。**組み立てて表示するだけで、送らない**

3 は `place_order` が実際に送るのと同じ関数で作っているので、表示と送信内容はずれない。
残る未検証は「発注の応答の解釈」だけになる。

戦略も検証記録も要らない。**この確認と、本番で動かしてよいかは別の問題になる。**

## 数字についての注意

`costs.py` の料率は調査時点（2026年8月）の公開情報。
**bitbank の Taker 手数料は確認できておらず、仮の値が入っている**（`unverified=True` で警告が出る）。
口座を開いたら管理画面の実数値で上書きすること。往復0.05%の差が、
日に数回転する戦略の損益を大きく変える。

## 制度面のメモ

- 国内の個人向け暗号資産証拠金取引は**レバレッジ2倍が上限**（2020年5月施行の内閣府令）。
  `BacktestConfig(leverage=...)` は2を超えると例外を投げる
- **現物ではショートできない。** ショート戦略には証拠金取引口座が必要。既定では無効
- 2026年8月現在、売買益は**雑所得・総合課税**（最高約55%）。損失の繰越控除は不可。
  分離課税（20.315%）への移行は決まっているが、適用は早くて2028年1月の見込み
- **販売所形式は片道3〜6%。** `--cost dealer` で試せるが、往復9%は短期売買では取り返せない。
  必ず取引所（板取引）形式を使うこと

## 次にやること

上の「使い方」を上から順に実行するだけ。要点は5つ。

1. **リポジトリのルートで実行する。** ホームディレクトリではない
2. `pytest trading/tests -q` を通す（エンジンを信じてよいか確認）
3. `--show-required-return` で、自分の元本だと1日いくらが何%にあたるかを見る
4. 手元で実データを取得する（**開発環境から取引所APIには到達できない**）
5. `--compare-all --walk-forward 6` で、買い持ちを安定して上回る戦略があるか探す

口座とAPIキーがあるなら、5と並行して `run_live.py --check-connection` を通しておける。
**発注しないので、戦略が見つかるかどうかとは独立に進められる。**

**どの期間でも買い持ちを上回る戦略が見つからなければ、そこで止める。**
見つからないと分かることが、この基盤の一番の成果になりうる。

実データで見つからなかったときに、その結論を信じてよい理由が陽性対照になる。
`--regime intraday` で検出できることを確認済みなので、
「何も無かった」を「壊れていた」と取り違えずに済む。
