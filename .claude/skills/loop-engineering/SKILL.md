# loop-engineering(自走ループの設計/レビュー)

`/loop` はプロンプトやスラッシュコマンドを一定間隔で再実行するだけの機構で、**それ単体には停止判断も検証も記憶も無い**。この状態で回すと記事でいう Blind/Tangled/Nodding/Amnesiac/Manual Loop のどれかに落ちる。このスキルは、ループを組む・回す・レビューするときに、その落とし穴を塞いで精度を上げるための手順を持つ。

設計思想・原理・アンチパターンの"なぜ"は `notes/playbook/loop-engineering.md` に置いた(このスキルでは再掲しない)。コピペ可能なテンプレートは `references/` にある:

- `references/morning-triage.SKILL.md` — 発見(Discovery)用の triage スキル雛形
- `references/reviewer.md` — 検証("no"と言う扉)用の敵対的レビュアー雛形
- `references/state.md` — 永続化用の状態ファイル雛形
- `references/triage-workflow.yml` — スケジューリング用の GitHub Actions 雛形(3層キャップ入り)

## 使いどころ

- ユーザーが `/loop` を素で回そうとしている/回している → 下の5つの動きが揃っているか点検し、欠けている動きを足す。特に**検証・永続化・キャップ**が抜けていないか。
- 「定期的に自動で回したい」系の依頼 → 発見からスケジューリングまで一式を、テンプレートを土台に組む。
- 既存ループのレビュー依頼 → 末尾のチェックリスト(5つの病 + 4つの負債の監査)で診断する。

## 手順: 5つの動きを1つずつ据える

どれか1つでも欠けると、ループは走らないか、走っても前に進まない。既に在るものは飛ばし、欠けているものだけ足す。

1. **発見(Discovery)**: 「今日/今回何をやるか」をループ自身に選ばせる。人が候補リストを毎回渡している時点で自動化されたのは実行だけ(Blind Loop)。入力源は具体コマンドまで落とす(例 `gh run list --status failure`)。判定(Judge)を skill の中に書く。→ `references/morning-triage.SKILL.md`

2. **委任(Handoff)**: finding ごとに専用の作業空間を割り当て、隔離する。並列で回すなら **finding 1つにつき git worktree 1つ**(`git worktree add`)。作業ディレクトリを共有させない(Tangled Loop 回避)。`main` では作業しない。並列数は「マシンが回せる数」でなく「自分が正直にレビューできる PR 数」で上限を切る。

3. **検証(Verification) — "no"と言う扉。最重要**: コードを書いたのと**同じエージェントに採点させない**。別プロンプト・できれば別モデルの評価者を立てる。デフォルト懐疑(ASSUME BROKEN)、意図でなく**挙動**で判定(実際に動かす・テストを実行し実出力を貼る・Playwright/curl で叩く)、REJECT には必ず具体的理由を添える。停止条件は生成器でなく新鮮なモデルに判定させる(`/goal`)。`/loop`(間隔再実行・停止判断なし)と `/goal`(条件が true と判定されるまで)は別物。→ `references/reviewer.md`
   - **酸のテスト**: 直近5ターン以上、評価者が一度も no を言っていないなら、評価者は働いていない。

4. **永続化(Persistence)**: 成果は会話(context)でなくディスク(memory)に書く。context は毎ターン消える。状態ファイルは最低4列 `| finding | source | priority | status |` を持ち、**必ず repo に commit する**(さもないと翌朝のランナーから見えず、毎日ゼロから再トリアージ = Amnesiac Loop)。→ `references/state.md`

5. **スケジューリング(Scheduling)**: 自分が覚えていることに依存しないトリガーを掛ける(掛けなければ Manual Loop = 一度走らせて忘れたスクリプト)。判断軸は「この仕事はラップトップを離れられるか」の一点 — 離れられるなら Cloud(GH Actions, 最小1時間)、ローカルファイルを毎分見るなら `/loop`/desktop(要マシン+セッション)。→ `references/triage-workflow.yml`

## 必ず据える2つの扉(安全)

これらが無い自走ループは組まない/回さない。

- **キャップ(サーキットブレーカー)**: **走らせる前に**3層を設定する — per-run タイムアウト・daily budget・max retries。キャップは節約策でなく、青天井のリスクを有界にする装置。「バグが一晩回る」を止めるのはこれ。
- **人間の扉**: PR は**自動マージしない**、不確実なものは `./inbox/` へ落として人間に回す(PR にしない)、1日1本サンプル PR を読んで「何がなぜ変わったか」自分の言葉で説明できるか自問する。扉は「人が必ず通るから」でなく「扉が在ること自体が"通れる立場"を保つから」在る。

## チェックリスト(組んだ/レビューするループの診断 = 5つの病 + 4つの負債の監査)

- [ ] **発見**: 今日やる仕事をループ自身が選んでいる(人が候補リストを渡していない)。入力源は具体コマンドまで書かれている ← Blind Loop
- [ ] **委任**: finding ごとに隔離された作業空間があり、`main` で作業していない。並列上限は「レビューできる PR 数」で切ってある ← Tangled Loop
- [ ] **検証**: 生成器と別の評価者が居る(できれば別モデル)。ASSUME BROKEN で、コードを読むだけでなく実際に動かして挙動で判定している。REJECT に理由が付く。直近で一度は no を言っている ← Nodding Loop / VERIFICATION DEBT
- [ ] **永続化**: 状態がディスク上の4列以上のファイルにあり、repo に commit されている。翌ターンがそこからバトンを受け取れる ← Amnesiac Loop
- [ ] **スケジューリング**: 自分の記憶に依存しないトリガーが掛かっている。仕事の性質(ローカル/クラウド)とスケジューラが合っている ← Manual Loop
- [ ] **キャップ**: per-run・daily budget・max retries の3層が、初回実行の**前に**設定されている ← TOKEN BLOWOUT
- [ ] **人間の扉**: 自動マージしない。不確実なものは `./inbox/`。1日1本サンプルを読む運用が決まっている ← COMPREHENSION ROT / COGNITIVE SURRENDER
- [ ] ループは自分が増幅したいもの(理解)を増幅する向きに組まれている。怠惰を増幅する向きになっていない
