# rakuten-x-plan(STEP4: 流入設計 / X)

公開済みの比較記事へ X から流入を送る。**X は資産ではなく流入元**という位置づけ(理由は `notes/playbook/rakuten-affiliate.md` の「媒体の選択」を参照)。定型作業なので安価なモデルで回してよい。

## 設計上の前提(ここを外すと凍結する)

この Skill の本体は文章生成ではなく**連投判定の回避**にある。楽天ガイドラインは同一・類似内容の連投(自身の RT・引用 RT を含む)と複数アカウントでの同一投稿を禁止し、X も Platform Manipulation and Spam Policy で重複・実質的に類似した投稿を禁止している。**「同じ記事を言い換えて何度も流す」は両方に抵触する。**

- **X にアフィリエイトリンクを直接貼らない。** 送り先は自分の記事。記事側にリンクと PR 表記がある構成にする。X 側でリンクを改変・短縮するリスクも同時に消える。
- **投稿は 1 日 2〜3 本まで。** 実務相場であり、それ以上は本数を稼いでも凍結リスクの方が増える。
- **同一記事の再投稿は切り口を変え、最低 2 週間空ける。** 台帳で履歴を管理する。
- **開示は安全側に倒す。** X の Paid Partnerships Policy はアフィリエイトコミッションが発生する宣伝に投稿作成時の開示設定(Content Disclosure トグル)を求めている。記事経由でも収益が発生する以上、ONにしておく。ONにすれば #ad 等の別途表記は不要とされる。

## 手順

1. **台帳の確認**: `notes/rakuten/ledger.md` の X 投稿履歴を読む。**対象記事を直近 2 週間以内に投稿していないか、過去にどの切り口を使ったかを必ず確認する。** 生成前に行う。
2. **対象記事の特定**: 記事表から状態が「公開済み」のものを選ぶ。URL が確定していること。
3. **投稿案の生成**: 下のプロンプトを実行する。過去に使った切り口を必ず渡し、重複を避けさせる。
4. **重複チェック**: 生成された案と過去投稿を突き合わせ、**言い換えにすぎないものを落とす**。切り口が実質同じなら本数を減らす。5 本出して 2 本しか残らないなら、それが正しい結果。
5. **表現チェック**: 煽り・保証表現・効能の断定が無いかを確認する。
6. **投稿と記録**: 投稿は手作業(自動投稿・BOT は楽天・X 双方で禁止)。投稿したら `notes/rakuten/ledger.md` の X 投稿履歴に日付・記事・切り口を記録する。変更は diff で提示し、push はユーザー明示指示まで保留する。

## プロンプト(投稿案の生成)

```
次の記事へ X から流入を送るための投稿案を5本作ってください。

記事タイトル：[タイトル]
記事URL：[URL]
想定読者：[ターゲット]
この記事で過去に使った切り口：[無ければ「なし」]

条件
・5本すべて異なる切り口にすること。言い換えや語尾違いは同一とみなす
・過去に使った切り口とも重複させないこと
・切り口の例：比較の結論だけ / 失敗談 / 選び方の基準 / 特定の使用場面 /
  意外だった点 / よくある誤解
・1本140字以内(全角)
・煽り表現、「絶対」「必ず」などの保証表現、効果や効能の断定を使わないこと
・ハッシュタグは2個まで。羅列しないこと
・記事を読まなくても単体で情報として成立する書き出しにすること
  (リンクだけ貼る投稿にしない)

各案について、次を出してください。
・投稿本文
・使った切り口(1語で)
・想定する反応(なぜこれが読まれるか、1行)

表形式で出力してください。
```
