# fable-like output style 運用ノート

Sonnet / Opus を Fable 5 的な行動様式（結論先行・即行動・検証規律・スコープ規律）で
運用するための output style。本体は `.claude/output-styles/fable-like.md`。

素材は Anthropic 公式の「Prompting Claude Fable 5」ガイド。Fable の操縦スニペットを
裏返して「Fable が自然にやるべきこと」の行動仕様書として読み、8項目に凝縮したもの。

## 導入

このリポジトリではプロジェクトレベル（`.claude/output-styles/fable-like.md`）で
すでに有効。他プロジェクトや個人環境で使う場合:

1. `~/.claude/output-styles/fable-like.md` に本体をコピーする
2. `/config` → Output style → `fable-like` を選ぶ
3. `/clear` か新セッションで有効化される

frontmatter の `keep-coding-instructions: true` により、Claude Code の
コーディング指示は全部維持したまま「振る舞い」だけが追加される。
CLAUDE.md（ユーザーメッセージ扱い）と違い、output style は既定指示そのものに入る。

## effort とのペア設定

公式のモデル移行ガイドの対応: Fable の high は Opus 4.8 の xhigh に相当する。

- Sonnet に切替: output style `fable-like` + effort **high**
- Opus に切替: output style `fable-like` + effort **xhigh**

## 使い分けの3場面

1. **コスト**: Fable 5 は Opus 4.8 の2倍の価格。全セッション Fable は不経済
2. **レートリミット**: 下位モデルへの退避時も型を揃える
3. **拒否フォールバック**: Fable の safety classifier が cyber/bio 系タスクを
   拒否した場合、公式が Opus 4.8 へのフォールバックを案内している

## サブエージェント用凝縮版

サブエージェント（Task で spawn する worker）には output style が効かない。
タスク指示の末尾に以下を貼る。

```
以下は行動規範。全て命令。
- **結論先行**: 報告の最初の一文で「何が起きたか/見つかったか」に答える。断片・矢印チェーン・自作ラベルで圧縮しない。完全な文で書く
- **即行動**: 行動に足る情報が揃ったら行動。確定済み事実の再導出・決定済み事項の再審議・採らない選択肢の陳列をしない。迷ったら推奨を1つ
- **進捗の実証**: 報告前に各主張をツール結果と突合。未検証は未検証と明言。テスト失敗は出力ごと報告。捏造進捗は最悪の失敗
- **スコープ規律**: 要求以上の機能追加・リファクタ・抽象化禁止。動く最小をやる。起こり得ないシナリオへの防御コード禁止
- **ターン終了規律**: 「これから X します」で終わらない。実行してから終える。停止してよいのは完了時かユーザーにしか出せない入力待ちのみ
- **境界**: 問題の説明を受けた時の成果物は評価であって修正ではない。状態変更コマンド前に証拠がその操作を支持するか確認
```

## 書き方の原則（メンテ時に維持すること）

1. 制約は命令形で法制化し、理由の長い説明を添えない
2. 好む書き方と嫌う書き方を対で指定する（「結論から書け」だけでなく
   「矢印チェーンで圧縮するな」まで書くと効きが違う）

## 移植できないもの

移植できるのは行動様式だけ。以下はモデルの地力であり指示文では埋まらない:

- first-shot correctness（複雑な仕様を一発で正しく実装する率）
- 数時間単位の長期自律性
- dense な技術画像の読解精度
- 1M トークンコンテキスト（Sonnet は beta 対応、Opus 4.8 は 200K のまま）
