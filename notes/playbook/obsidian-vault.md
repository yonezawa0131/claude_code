# Obsidian vault(second brain)の設計

エージェント(Claude Code)が読み書きする知識基盤を Obsidian vault として運用するための設計書。Karpathy の llm-wiki 的発想に基づく: **知識ベースをコードベースのように扱う。Obsidian はエディタ、モデルはプログラマ、wiki がコード。** vault はただの Markdown フォルダなので、モデルを乗り換えても生き残る(モデル非依存)。

## 構造(4 要素のみ)

```
vault/
├── raw/          # 捕獲した素材を無加工で置く。読み取り専用の ground truth
│   └── ClaudeChat Memory/   # claude.ai 会話エクスポート(scripts/claude_export_to_obsidian.py が生成・更新)
├── entities/     # 具体物 1 つにつき 1 ページ(クライアント、競合、ツール、人)
├── concepts/     # 概念 1 つにつき 1 ページ(戦略、パターン、教訓)
└── INDEX.md      # 玄関。全ページを 1 行説明付きで列挙
```

- **raw/ はエージェントが書き換えない。** 同じノートを読んで書き直すサイクルを繰り返すと詳細が磨耗し誤りが複利で増える。compiled 側が壊れても raw から再コンパイルできるのが保険になる。
  - `raw/ClaudeChat Memory/` はインポートスクリプトだけが機械的に上書き管理する。手編集しない点は同じ。
- entities/ と concepts/ が「コンパイル済み」の知識。エージェントの仕事はコンパイル: raw/ の新素材を読み、entities/concepts のページを更新し、`[[wikilink]]` で繋ぐ。
- リンクはグラフの辺。検索型の知識ベースは成長するほどノイズが増えるが、リンク型 wiki は成長するほど強くなる。エージェントは全走査せず**リンクを辿って**答えに着く。
- INDEX.md があるから、全ファイルを開かずに何が存在するかを知れる。

## 書き込みルール(4 行)

1. 1 ファイル 1 教訓。冒頭に 1 行要約を置く。
2. 重複ページを作らず、既存ページを更新する。
3. 誤りと判明したノートは削除する。
4. raw と compiled を混ぜない。raw/ は書き換えない。

加えて出典の規律: compiled ページの主張には raw/ 内の元ファイルへのリンクを付ける。**出典リンクの無いページはフラグ対象**(信用せず、dream で検証・除去の候補にする)。

## 読み取りルール(コスト管理)

- CLAUDE.md は **vault を指すだけ**にする(200 行未満)。vault の内容を貼り込まない — 毎セッション自動ロードされる固定税になる。
- 読み方は pay-per-read: INDEX.md を見る → リンクを辿る → grep で絞る → 必要なページだけ開く。**フォルダ全読みは常に禁じ手。**
- 大きい問いは subagent に読ませる: 別コンテキストで 50 ページ読ませ、結論の 1 段落だけを受け取る。メインの context window には決定を置き、図書館は置かない。

## 維持ループ(放置した vault は 3 週間で死ぬ)

| 頻度 | 作業 | モデル tier |
|---|---|---|
| セッション毎 | 決定・失敗・確定パターンを日付付きノートで vault へ書く(hook / 記憶ルールで自動化) | セッションのモデル |
| 定期(日次目安) | compile: raw/ の新素材を entities/concepts へ反映 | 安価(Sonnet/Haiku) |
| 週次 | lint: 矛盾・重複・リンク切れの掃除 = **memory-dream Skill を実行** | 安価〜中位 |
| 週次 | synthesis: vault 全体を横断し「今週何が変わったか・何がドリフトしているか」を 1 ページ書く | 上位(Opus 級) |

ルーチン作業(ノート更新)を上位モデルに回さない。上位モデルが席代を稼ぐのは synthesis だけ。

## バックフィル(初期投入)

1. 手持ちを全部 raw/ に投げ込む: 会話エクスポート(スクリプトで自動)、ブックマーク、メモアプリの export、過去リサーチ。
2. エージェントに compile を指示する。ただし 2 つの規律で正直に保つ:
   - 変更は必ず **diff で提示**させる(「更新した」という主張ではなく before/after)。
   - raw/ への出典リンクの無いページはフラグする。
3. 一括で終わらせようとしない。会話履歴が数百件あるなら dream のたびに少しずつ消化するインクリメンタル方式でよい。

## プロジェクトへの接続

各プロジェクトの CLAUDE.md に 3 行入れるだけで、全プロジェクトが vault を参照するようになる:

```markdown
## knowledge
- 開始前に ~/vault/entities/ と ~/vault/concepts/ の関連ページを読む
- 事業・クライアント・読者に関する主張は vault のページを根拠にする
```

## 同期の注意(vault が死ぬ場所)

**同期系は 1 本にする。** エージェントがファイルを書いている最中に iCloud / Obsidian Sync が同期すると、conflicted copy とフォルダ破損が起きる。チェックポイント層は git — 明示的に commit した時だけ版が確定する構成が生き残る。

## 採用しなかったもの(判断メモ)

- `/goal` によるバックフィル自動化: 元記事が主張する Claude Code 機能として確認できない。バックフィルは通常の指示(+ 上記の diff / 出典規律)で足りる。
- 外部リサーチスタック(ScrapeCreators / X MCP / Firecrawl / Perplexity 等): 有償・ニッチ依存。導入する場合も骨格だけ持ち込む: 問いをサブ問いに分割 → 並列 fan-out → 主張・出典 URL・日付の「受領書」形式 → **リサーチしていない別コンテキストの懐疑エージェントが反証を試み、生存した主張だけ** vault へ、日付+出典+失効日付きで着地。
- 記事中の数値(精度 70→90%、前世代比 3 倍改善等): 出典が薄く検証不能。構造の妥当性とは切り離す。
