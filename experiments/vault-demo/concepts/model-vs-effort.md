# モデル対 effort(model-vs-effort)

モデル = 何を知っているか(凍結された重み・能力)、effort = どれだけ働くか(完了と見なすまでの徹底度)。

#type/concept #domain/model #layer/rule

## 主張

- **モデル変更 = 処理する凍結重み一式の差し替え**。重みは訓練時に固定され推論時は読み取り専用 — プロンプトも CLAUDE.md もコンテキストも重みを変えない。コンテキストにできるのは予測の steering(操縦)だけで、teaching(学習)ではない。訓練後に登場したライブラリを docs 経由で使わせても、そのリクエスト限りでモデルには何も残らない。
- **effort は thinking 時間だけを制御するのではない**: 読むファイル数、検証の量(テスト実行・二重チェック)、確認を挟まずに多段タスクを進む距離を制御する。低 effort では自力で調べるよりユーザーに文脈を聞く方へ倒れやすい。
- 結果に不満なときは**まず設定より先にコンテキスト(プロンプト・ツール定義・Skill・タスクの切り方)を疑う**。それでも間違うなら「知らなかったのか(→ モデルの問題)、頑張らなかったのか(→ effort の問題)」で切り分ける。
- effort は**タスク毎の判断ではなく一般的な好みとして**設定する。基本はデフォルト(モデルが「大半の人がそのタスクに使いたい量」にスケールする水準)のままにし、ドメインとして強い好みがあるときだけ意図的に上書きする。
- **ルーチンが続いたら小さいモデルへ落とす**(品質コストゼロの純益)。一方で**難しい多段作業は等式が反転**しうる — 小さいモデルは能力の限界に向かって反復を燃やすため、単価は高くても大きいモデルの方が**タスク単位の総額**では安くなり得る。
