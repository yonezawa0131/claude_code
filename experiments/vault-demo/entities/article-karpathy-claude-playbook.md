「天才アンドレイ・カーパシーのClaude活用術」(X @ai_ai_ailover, 2026-07-08)の要約と、この vault へ取り入れる候補の抽出。

#type/article #domain/agent #layer/procedure

## 記事の要旨

カーパシーの Software 3.0 思想(プロンプト = 自然言語という新しいプログラム)を Claude の 2026 年時点の機能群に接続した「実践フレーム」。著者自身が明記する通り**公式のモードではなく再構成**である。骨子:

1. **「AIに聞く」から「AIで作る」へ**: Claude はチャット相手ではなく、コードを書き・テストを回し・外部システムに接続し・Artifact を残す「実行環境」。
2. **人間の役割の転換**: カーパシーは 2025 年末頃から手書き中心 → エージェント中心に移行したとされる。人間は全行を書く人ではなく、目的・制約・成功条件を定義し、生成物を「鷹のように」読む人になる。エージェントの誤りは構文エラーではなく、微妙な概念ミス・勝手な前提・過剰な抽象化に移っている。
3. **命令ではなく成功条件**(記事の核心): 手順を細かく指示するより、検証可能なゴール+テストを与えてループさせる → [[success-criteria-loop]] として抽出。
4. **実装後の単純化レビューを必須にする**: LLM は過剰抽象化しがちだが「もっと単純に」と問えば縮められる。作らせた後に削らせ、最後に人間が読む。これが slop 化を防ぐ最小条件。
5. **環境設計 > 毎回のプロンプト**: CLAUDE.md = プロジェクト憲法、Skills = 業務マニュアル、Subagents = 観点の分離(実装する AI と疑う AI を分ける)、MCP = 現実システムへの感覚器官。
6. **価値は時短ではなく行動範囲の拡張**: 以前なら面倒で作らなかった小ツール・テスト・整理を「ついでに作るか」にすることがレバレッジ。
7. **モデルは配分する**: 日常は Sonnet 5、重い設計・レビューは Opus 4.8、最重要タスクは Fable 5、安価な下処理・サブエージェントは Haiku 4.5。全部を最強モデルに投げない。
8. **避けるべき失敗**: 完了報告を信じすぎる(証拠を要求する)・いきなり大規模変更・CLAUDE.md を書かない・レビュー専門エージェントを置かない・セキュリティ用途の境界超え。

7 原則の合言葉: 「細かく命令するな。成功条件を与えろ。コードを書かせろ。ただし、必ず読め。テストを書かせろ。通るまでループさせろ。大きく作らせろ。最後に単純化しろ。毎回プロンプトを書くな。環境を作れ。Claude を使うな。Claude と働け。」

## この vault / リポジトリへの取り入れ候補

**既に持っているもの(答え合わせになった点)**:

- モデル配分(§2)は [[model-vs-effort]] / [[maintenance-loop]] の tier 分けと同じ結論。新規性なし。
- 「実装する AI と疑う AI を分ける」(§13)は [[playbook-obsidian-vault]] のリサーチ懐疑エージェント(反証を試み生存した主張だけ着地)と同型。
- 「変更は diff で提示・出典リンクの無いページはフラグ」([[write-boundary]] 系の規律)は、記事の「完了報告に証拠を要求せよ」(失敗1)の vault 版に相当。

**新しく取り入れる価値があるもの**:

1. **成功条件駆動ループ** → [[success-criteria-loop]] として concept 化(本コンパイルで実施)。Skill(vault-compile / synthesis / dream)のプロンプトに「完了の定義(done_definition)」を明示する改修候補。
2. **完了報告テンプレ**(失敗1): 「実行したコマンド / 通ったテスト / 確認したファイル / 未確認リスク」を分けて報告させる形式。playbook の「diff で提示」規律に足す 1 行として有効。
3. **単純化レビューの定型化**(§12): 実装系タスクの最後に「削る」パスを必ず挟む。Claude Code には /simplify・/code-review が既にあるので、「playbook 側にいつ呼ぶかを書く」だけで取り込める。
4. **XML タグでの文脈分離**(§7): task / context / success_criteria / constraints / output を分ける書式。Skill プロンプトを整える際の小さな習慣として採用可。

**採用しないもの**: 記事中の数値・時事逸話(Sonnet 5 価格、輸出管理の経緯、「2025年12月に相転移」等)。下記の検証メモ参照。

## 検証メモ(出典の規律)

- 記事は一次出典(講演・投稿・公式発表)への言及はあるがリンク実体は未確認。**カーパシーの Anthropic 参加(2026年5月・Reuters 報道とされる)、Sonnet 5 の価格・API 仕様、Fable/Mythos の輸出管理経緯などの個別事実はこの vault では検証できていない**。
