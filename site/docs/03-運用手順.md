# 運用手順

## 0. 公開前に埋めるもの

`src/consts.ts` の以下は仮の値のままなので、公開前に必ず変更する。

| 項目 | 現在 | やること |
|---|---|---|
| `SITE.url` | `https://rokujo-desk.pages.dev` | 独自ドメインを取ったら書き換える。canonical・OGP・sitemap すべてがこの値を見ている |
| `SITE.author` | `運営者` | 実名またはハンドルネーム。未設定だと運営者情報ページに警告が出る |
| `SITE.email` | 空 | 連絡先。未設定だとお問い合わせページに警告が出る |

`src/pages/about.astro` のプロフィール文も、自分の状況に合わせて書き換える。「なぜこのテーマについて書けるのか」が伝わることが、E-E-A-T の Experience にあたる。

## 1. 公開までの流れ

手順が長いので、別のドキュメントに分けている。

| やること | 参照先 |
|---|---|
| ホスティングの選定、ドメイン取得、Cloudflare Pages への接続、GA4 と Search Console の設定 | [05-デプロイ.md](05-デプロイ.md) |
| どのASPを主軸にするか、登録の順番、リンクの貼り方、表示義務 | [06-ASP設定.md](06-ASP設定.md) |

順番としては、**記事を5〜10本書く → デプロイして Search Console に登録 → 流入が出始めてから ASP に申し込む**。

Amazonアソシエイトは「180日以内に3件の適格販売」が条件で、達成できないとアカウントが閉鎖され同じIDで再開できない。**流入がない段階で申請すると空振りする。**

## 2. 記事を追加する

```bash
cd site
npm run dev              # http://localhost:4321
```

1. `src/content/posts/（英数字のファイル名）.md` を作る
2. `docs/04-記事テンプレート.md` の frontmatter をコピーして埋める
3. `npm run audit:content` でチェック
4. `npm run build` が通ることを確認
5. commit → push → Cloudflare Pages が自動デプロイ
6. Search Console でインデックス登録をリクエスト

`draft: true` にしておくと本番ビルドから除外される。書きかけを push しても公開されない。

## 3. 公開後にやること

- **記事は書き直す。** 順位が付かない記事は、キーワードを変えるか、内容を足す。`updatedDate` を入れると更新日が表示される
- **Search Console の検索クエリを見る。** 自分が想定していないキーワードで表示されていることがある。そのキーワードで記事を書き直すか、新しく書く
- **リンク切れを定期的に確認する。** 製品は廃番になる。価格の記述も古くなる
