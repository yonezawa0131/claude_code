# デプロイ

6畳デスク研究所をインターネットに公開するための手順です。

## ホスティングは Cloudflare Pages を使う

複数の無料ホスティングサービスを検討しましたが、**Cloudflare Pages を採用します**。商用利用が可能で、帯域幅が無制限であり、日本国内にエッジ拠点が複数あるためです。

| サービス | 無料枠での商用利用 | 帯域幅 | ビルド回数 | 日本国内のエッジ拠点 |
|---|---|---|---|---|
| **Cloudflare Pages** | **可** | **静的アセットは無制限** | 500回/月（ソフトリミット） | **あり（東京・大阪ほか）** |
| Vercel (Hobby) | **不可** | — | — | 大阪をリージョン指定可 |
| Netlify | 可 | クレジット制：月300クレジット | 月300クレジットの枠内 | なし（シンガポール経由） |
| GitHub Pages | グレーゾーン | ソフトリミット100GB/月 | ソフトリミット10回/時間 | — |
| Firebase Hosting (Spark) | 未確認 | 転送量360MB/日 | — | — |

### 他のサービスを選ばない理由

**Vercel (Hobby)** は規約で「personal or non-commercial use」と明示されており、アフィリエイトサイトの運営は商用利用にあたるため規約違反となります。Pro プラン（月額$20〜）以上への加入が必要です。

**GitHub Pages** の規約には「commercial transactions を主目的とするサイト」の禁止が記載されています。アフィリエイトサイトが該当するかはグレーゾーンであり、後々の問題を避けるため推奨できません。

**Netlify** は日本国内にCDN拠点がなく、シンガポールを経由するため、レスポンス速度で不利になります。

## ドメインを取る

独自ドメインはレジストラから取得します。複数のサービスを比較しました。必ず**更新価格**で判断してください（初年度のキャンペーン価格ではなく）。

| レジストラ | .com 更新価格の目安 | Whois代行 | 備考 |
|---|---|---|---|
| Xserverドメイン | 1,298〜1,428円 | 無料 | 追加の名目上乗せなし |
| ムームードメイン | 1,728〜2,112円 | 無料 | ロリポップ併用で特典あり |
| お名前.com | 1,700〜1,800円程度 | 同時申込みなら無料、後から追加は年1,078円 | 「サービス維持調整費」に注意 |
| Cloudflare Registrar | 約$10.44/年 | 標準で非公開 | **移管専用（新規登録不可）、.jp 非対応** |

お名前.comは見た目の表示価格に「サービス維持調整費」という別名目が上乗せされるため、実質価格が高くなります。Xserverドメインまたはムームードメインでの取得をお勧めします。

Cloudflare Registrar は原価提供でマークアップがないため安価ですが、既存ドメインの移管に限定されており、新規登録には対応していません。また .jp ドメインは取り扱っていません。

## Cloudflare Pages に接続する

### 準備

- Cloudflare のアカウントを作成します
- 取得したドメインをCloudflareのネームサーバーに変更します（レジストラの管理画面から操作）

### GitHub リポジトリの接続

1. Cloudflare ダッシュボードで「Pages」を開きます
2. 「プロジェクトを作成」から「Git に接続」を選択
3. GitHub の認可画面で認可し、`site` ディレクトリを含むリポジトリを選択
4. 以下の設定値を入力します

```
フレームワークプリセット : Astro
ビルドコマンド          : npm run build
出力ディレクトリ        : dist
ルートディレクトリ      : site
Node バージョン         : 22（環境変数 NODE_VERSION = 22）
```

環境変数の設定方法：プロジェクトの設定画面で「環境変数」セクションを開き、キー `NODE_VERSION`、値 `22` を追加します。

5. デプロイします。ビルドログを確認し、エラーがないことを確認
6. デプロイ後、プロジェクト設定で「カスタムドメイン」から独自ドメインを接続します
7. Cloudflare が自動的にSSL/TLSの証明書をセットアップします

以降、GitHub に push するたびに自動的にビルド・デプロイが行われます。

## アクセス解析を入れる

### Google Analytics 4 (GA4) の設定

GA4 は新規プロパティで「拡張計測機能」が既定で有効になっており、コード変更なしでアウトバウンドリンク（アフィリエイトリンククリック）を自動計測できます。

設定は簡単です。Google Analytics の管理画面から新しいプロパティを作成し、測定ID（G-で始まるID）をコピーします。

リポジトリの `src/consts.ts` を開き、`ANALYTICS.ga4Id` に測定IDを設定します：

```typescript
export const ANALYTICS = {
  ga4Id: 'G-XXXXXXXXXX', // ここに測定IDを貼り付け
};
```

`ga4Id` が空でなければ、自動的にサイトに Google Analytics タグが出力されます。設定すると、プライバシーポリシーの記述も自動的に Google Analytics を名指しする内容に切り替わります。

### Cloudflare Web Analytics との比較

Cloudflare Web Analytics は Cookie を使わないため、同意バナーが不要という利点があります。ただし、任意のクリックイベント（アフィリエイトリンククリック）を計測する標準機能がありません。クリック計測には別製品の Zaraz が必要になるため、シンプルさを重視するなら GA4 のほうが素直です。

## Search Console に登録する

Search Console は順位を上げるツールではなく、インデックス状況と検索クエリを確認するためのものです。ここを見ないと、どのキーワードで表示されているかが分からないまま記事を書き続けることになります。

1. Google Search Console にアクセスし、ドメインプロパティ（DNS認証）を選択して登録します
2. Cloudflare の DNS 設定画面で、Search Console が指示した TXT レコードを追加します
3. 認証が完了したら、Google Search Console でサイトマップを登録します
4. サイトマップの URL は以下の通りです

```
https://（ドメイン）/sitemap-index.xml
```

新規ドメインの場合、検索エンジンの評価が安定するまで**3〜6ヶ月**かかります。その間は定期的に検索パフォーマンスを確認し、改善が必要な箇所を対応します。

## デプロイ前のチェック

本番環境にデプロイする前に、以下のコマンドを実行してビルドとテストが通ることを確認します：

```bash
npm run build
npm run audit:content
```

`npm run build` は TypeScript の型チェックとテストを含みます。エラーが出た場合は修正してから再度実行してください。

`npm run audit:content` はコンテンツの検証を行います。両方のコマンドが成功すれば、デプロイの準備ができています。
