# 記事テンプレート

`src/content/posts/` に `.md` を置くと記事になる。ファイル名がそのまま URL になる（`rental-monitor-arm.md` → `/posts/rental-monitor-arm`）。

URL は日本語を避けて英数字にする。日本語 URL はエンコードされて共有時に崩れる。

## frontmatter の全項目

```yaml
---
title: 賃貸でモニターアームは使えるか
description: 40文字以上120文字以内。検索結果に出る文章なので、記事の要約ではなく「読むと何がわかるか」を書く。
publishDate: 2026-08-01
updatedDate: 2026-09-15      # 任意。更新したら必ず入れる
category: monitor             # layout / desk / monitor / chair のいずれか
tags: [賃貸, モニターアーム]
heroImage: ./images/foo.jpg   # 任意。記事と同じ階層に images/ を作って置く
heroImageAlt: 天板にクランプを固定したところ
draft: false                  # true の間は本番ビルドから除外される
noindex: false                # 検索に出したくないときだけ true
hasAffiliate: true            # false にすると PR 表記が消える。リンクを貼るなら必ず true

keyPoints:                    # 記事冒頭の「結論」ボックス。3〜4行
  - 天板の厚みが1.5〜4cmの範囲なら、ほとんどのクランプ式が使える
  - 壁にぴったり付けた机では、アームの支柱が入らず設置できない

products:                     # 比較表と商品カードの元データ
  - name: エルゴトロン LX デスクマウント モニターアーム
    shortName: エルゴトロン LX
    url: ''                   # アフィリエイトリンク。空なら「リンク準備中」と表示される
    price: 16,800円
    rating: 4.5               # 自分で使った製品にだけ付ける（tested: false だと audit でエラー）
    tested: true
    pros:
      - 可動域が広い
    cons:
      - 支柱が太く、壁との距離が必要
    specs:
      対応天板厚: 1.0〜6.0cm
      耐荷重: 11.3kg

faq:                          # FAQPage 構造化データになる
  - q: 天板が薄いと使えませんか
    a: 1cm未満の天板は、クランプの締め付けで割れることがあります。

related: []                   # 関連記事の id（ファイル名から拡張子を取ったもの）を明示指定
---
```

## 本文の構成

AI 検索に引用されやすく、かつ読者が離脱しにくい形は共通している。

```markdown
結論から書く。この記事で答える問いと、その答えを最初の2〜3文に置く。

## 「置けるか」を決めているのは何か

見出しの直後に、その節の結論を1〜2文で書く。詳細はそのあとに続ける。

## 具体的な数字

表と箇条書きで構造化する。数字には必ず根拠（規格名・計算式・実測）を添える。

## 実際に測ってみた

自分で確認したことは、確認したと明記する。写真があるとなお良い。

## どう選ぶか
```

### 守ること

- **使っていない製品を「使った」と書かない。** スペック比較と実機レビューは、記事内で言葉として区別する。`tested: true` は実際に購入・使用したものだけ。
- **数字には根拠を書く。** 「広めに取りましょう」ではなく「立ち座りに最低 75cm 必要（出典）」と書く。この一次情報性が、AI 要約に食われないための唯一の防御になる。
- **身体への効果を断定しない。** 「腰痛が治る」は薬機法・景表法の領域に入る。「長時間座ったときの疲れ方が変わった」のように、自分の体験として書く。
- **最上級表現を使わない。** 「No.1」「最高」には客観的な根拠の提示義務が生じる。
